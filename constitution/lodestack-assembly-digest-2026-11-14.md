## 1. Assembly meta-principles

- Constitution = ideal model written from scratch, deliberately ignoring the
  current setup. The current setup is an observation source only.
  Derivation = gap analysis ideal vs reality. Verdict categories:
  fix-reality / amend-ideal (receipt) / deliberate-ideal-rename /
  boundary-difference / publish relationship (upstream source to shippable
  copy).
- The constitution text is a high-level sketch on purpose. Specifics surface
  and get made precise DURING assembly. Do not block on the sketch being
  incomplete.
- SNAPSHOT DOCTRINE (proposal, endorsed by Devin's tse-recipes SHA pin):
  every derived skill carries a dated constitution snapshot reference
  (constitution-SHA header). Constitution iteration supersedes derivations,
  it never blocks them.
- Build order LOCKED: Memory first, then Edit, then the two Standards skills.
  Reason: dependency, not testing yield. Edit's VERIFY has a LODE check and
  REASON cites ADRs; both presuppose the Memory contract's artifacts.
  AGENTS.template.md also ships in the Memory skill.
- Naming LOCKED: `lodestack-*` (lodestack-memory, lodestack-edit, ...).
  Fresh Mistral registry entries; old UUIDs orphaned, noted.
- AGENTS.md is NOT a 5th skill. It ships as AGENTS.template.md, home:
  lodestack-memory. Locked by Damian.
- One contract at a time, end-to-end (SKILL.md + Reference.md + refs/).

## 3. Gates and cognitive ownership

- Developer IS the gate. Technically the weakest gate (no automation, human
  factors), but the only NON-DELEGABLE one. Machine gates check what is
  decidable; the developer checks what is desirable.
- Gate the PRESENCE of judgment artifacts (drop reasons, picks, verdicts),
  never their content.
- Rubber-stamp alarm (Damian's own): mindlessly accepting the recommended
  option in each proposition menu. Rule: judge EVERY option, including the
  recommended one.
- ANALYZE semantics LOCKED: agent judges ACCEPT/REJECT first ("- first is
  agent"), developer reviews the table. Not a human gate on every element.
- DELEGATION CLAUSE (Devin proposal, Vibe-reconciled with cognitive
  ownership; PROPOSAL pending Damian's wording): a scope-bound pre-approval
  ("run autonomously until VERIFY fails or phase completes") is itself one
  quality gate decision replacing N low-quality rubber stamps. It also makes
  gate fatigue visible as a record. Suggested home: Edit contract or
  AGENTS.template.md.

## 4. Edit contract assembly notes

- Research-first is constitutional: "Research before solutions is
  mandatory" (global, covers Edit + ADR + Plan). v1's concrete ordering
  ports into Reference.md as the operationalization: codebase first, then
  official docs, then CLI help/man. Model memory is not a source.
- Reuse-first, no drive-by refactors, no new dependency without asking,
  bounded edit sites (long list means split the task): port per Devin's
  disposition, Damian endorsed "pick each and reason thoroughly".
- Per-change metrics in commit bodies: SLIMMED per Devin. The post-VERIFY
  table (summary / findings / potential issues) doubles as the commit body.
  Flagged for Damian's veto; do not assume.
- ALIAS TABLE for v1 to v2 renames (cheap, recommended): INTENT = REASON,
  IMPACT = ANALYZE, PROPAGATE absorbed into VERIFY (carrying commit/report
  duties). Old AGENTS.md copies in deployed repos use the old names.
- Behavioral edges to decide during authoring (all currently unspecified):
  a) VERIFY with no linter configured: skip or block? b) tree-sitter-edit
  fallback trigger: missing binary, unsupported grammar, parse failure, or
  verify failure? c) LODE check when lode/ absent: the AGENTS presence-check
  says "inform and offer installation"; VERIFY behavior still needs a line.
- Escape hatch: the 3-attempt bound breaks the inner loop. Satisfaction of
  REASON and VERIFY bounds the happy path; both are needed.
- tree-sitter-edit risk profile: 2 days old, no release tags, not installed
  locally. Mitigations: pin tse-recipes to SHA, keep text-diff fallback
  first-class in the contract text.

## 5. Standards contract refinements

- MISRA GATE SPLIT (Devin's key catch, endorsed): machine-checkable gates =
  targeted tests for BEHAVIORAL rules, analyzer configs (clang-tidy or
  cppcheck MISRA addon) for STATIC rules. One sentence in the contract
  prevents demanding a test where only an analyzer fits. Framing for Damian:
  the runtime-vs-static-analysis split familiar from ISO 26262 verification.
- MISRA distillation is PARAPHRASE-ONLY. Never verbatim rule text
  (copyright, bought copies). "Distilled rules win over sources" carries
  over from v1.
- Single mandatory universal tier (decision 2026-11-13): NO spirit/strict
  split. Per-language and per-domain needs are interpretation entries in
  Reference.md, rule purpose stated. Deviations become ADR opt-out receipts.
- Grug-brain: distill underlying RULES, not the caveman prose voice.
- Open flag: hard-but-not-machine-checkable rules still have no stated home.
- First principle verbatim: "Code with quality equal being maintainable by
  human without AI assistance, of junior level skill level".

## 6. ADR and executable specification

- VERIFICATION BLOCK (Devin proposal, endorsed; wording Damian's): every ADR
  carries a required block of testable assertions (given X, when Y, then Z).
  Makes ADR-to-Test derivation mechanical instead of hopeful. Keep it light:
  the ceremony audit already rejected heavy forced fields.
- ADR-FIRST is real, not aspirational: deployed agents (Devin, Le Chonk)
  worked ADR-first in practice. ADR = model (written first), lode = memory
  (status flip + receipts at acceptance). Derivation gap-row: current skill
  wording needs an interpretation entry stating ADR-first explicitly.
- Tier gate resolved NO: every ADR derives tests, uniform rigor.
  Proportionality lives in test size, not in ADR ceremony.
- TASKLIST SIZE BOUND (Devin proposal, endorsed): a TASKLIST growing past N
  steps means the ADR is too big; split it. Human-side hyperfocus guard,
  symmetric to LOCATE's bounded edit sites.
- Two-moment cadence remapped: ADR at decision (in practice: ADR first),
  lode update at acceptance.

## 10. RE contract (WIP, for later derivation)

- Cycle: TASK, MODEL, PROBE, PROOF. Code-editing variant inserts EDIT before
  PROOF. Hot loop: MODEL-PROBE(-EDIT)-PROOF until TASK resolves POSITIVE or
  NEGATIVE.
- COMPOSITION RULE (corrects Devin's suggestion): the RE cycle's EDIT stage
  INVOKES the Edit contract wholesale (REASON through VERIFY, unchanged).
  Two machines at different abstraction levels, composed. Do NOT map RE
  stages onto Edit-contract stage names or nest them inside ANALYZE.
- PROOF output (proposal, wording Damian's): PROOF = recorded, reproducible
  evidence, not "it worked once". RE TASKs are written as resolvable claims.
  Template: the Pop 8 cpu1rst session (marker + CPSR readback, recorded).
- RE scratch artifacts (disassembly dumps, probe logs) need a
  Memory-contract home at RE-skill derivation time. Known gap.
- Evidence base: the Pop 8 campaign log is the derivation source for this
  skill. Derivation is deferred until the four contracts stabilize.
