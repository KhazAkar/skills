Reference for Phase 1 / section Driver and runtime rules of the workflow.

## Errata first

Before debugging a driver, search the MCU and peripheral errata for the exact
part revision and peripheral name. Check reset values, clock dependencies,
reserved bits, timing workarounds, DMA restrictions, and interrupt behavior.
Record an erratum workaround in `lode/decisions/` before encoding it.

## MMIO in C

For one register, a volatile macro is explicit:

```c
#define UART_STATUS (*(volatile uint32_t *)0x40004000u)
#define UART_TXDATA (*(volatile uint32_t *)0x40004004u)

if ((UART_STATUS & (1u << 7)) != 0u) {
    UART_TXDATA = byte;
}
```

For a peripheral block, use a register struct with reserved space taken from
the datasheet:

```c
typedef struct {
    volatile uint32_t status;
    volatile uint32_t control;
    volatile uint32_t data;
    uint32_t reserved[5];
} UartRegs;

#define UART ((UartRegs *)0x40004000u)
```

Use fixed-width types, masks, and named bases from `lode/register-map.md`.
Never use a plain pointer for a register that hardware changes.

## MMIO in C++

Keep addresses and masks typed and visible:

```cpp
constexpr uintptr_t UartBase = 0x40004000u;
constexpr uint32_t TxReady = 1u << 7;

auto* const status =
    static_cast<volatile uint32_t*>(UartBase + 0x00u);
auto* const data =
    static_cast<volatile uint32_t*>(UartBase + 0x04u);

if ((*status & TxReady) != 0u) {
  *data = byte;
}
```

Prefer a register-block type when there are many registers. Avoid virtual
dispatch, exceptions, and allocation in hot paths; use `constexpr` policy
objects or templates for compile-time configuration.

## MMIO in Rust

Use the vendor PAC generated by `svd2rust`; do not duplicate register
addresses in application code:

```rust
let p = pac::Peripherals::take().unwrap();
p.UART.status.read().tx_ready().bit_is_set();
p.UART.control.write(|w| w.enable().set_bit());
p.UART.control.modify(|_, w| w.enable().set_bit());
```

`read()` snapshots a register, `write()` supplies a complete reset-safe value,
and `modify()` preserves unrelated fields. Follow the PAC's access semantics
and cite the datasheet and errata for unusual sequences.

## Short ISRs

An ISR should set a flag or push an item to a bounded queue, then return:

```c
static volatile sig_atomic_t rx_ready;

void USART_IRQHandler(void)
{
    rx_ready = 1;
}

int main(void)
{
    for (;;) {
        if (rx_ready != 0) {
            rx_ready = 0;
            service_rx();
        }
    }
}
```

For bytes, use a single-producer/single-consumer ring buffer. Define full and
empty behavior explicitly; never block, allocate, or print from an ISR.

```c
struct ring {
    uint8_t data[<capacity>];
    _Atomic size_t head;
    _Atomic size_t tail;
};
```

The C++ equivalent uses `std::atomic<size_t>` for indices and a fixed array.
Rust uses an interrupt-safe queue or an `AtomicBool` flag with a bounded
buffer. Keep ISR ownership and memory ordering documented.

## Shared state

C11 uses `_Atomic` for flags and indices; `volatile` is only for observable
MMIO or a value changed outside the abstract machine. Do not use volatile as a
replacement for atomicity:

```c
static _Atomic bool event_pending;
atomic_store_explicit(&event_pending, true, memory_order_release);
```

C++ uses `std::atomic<bool>` and the weakest ordering that preserves the
producer/consumer protocol:

```cpp
std::atomic<bool> event_pending{false};
event_pending.store(true, std::memory_order_release);
```

In Rust, protect non-atomic shared state with a critical-section mutex:

```rust
static STATE: critical_section::Mutex<
    core::cell::RefCell<Option<State>>
> = critical_section::Mutex::new(core::cell::RefCell::new(None));
```

Use `AtomicBool` for independent flags. Keep critical sections short and never
call a blocking peripheral operation while holding one.

## DMA and cache

On a cached Cortex-M7 or similar core, clean data cache before a peripheral
reads a TX buffer and invalidate after it writes an RX buffer:

```c
SCB_CleanDCache_by_Addr((uint32_t *)buffer, <length>);
start_dma(buffer);
wait_for_dma();
SCB_InvalidateDCache_by_Addr((uint32_t *)buffer, <length>);
```

Align buffers and lengths to the cache line, commonly 32 bytes:

```c
uint8_t rx[<length>] __attribute__((aligned(32)));
```

Alternatively place DMA buffers in a non-cacheable MPU or linker region.
Document ownership transitions, alignment, and the selected cache strategy in
an ADR; a clean cache alone does not fix a race with an active DMA transfer.

## Watchdog and reset cause

Initialize the watchdog early, before optional peripherals, and kick it only
from the healthy main loop:

```c
watchdog_init(<timeout>);
for (;;) {
    service_inputs();
    run_state_machine();
    watchdog_kick();
}
```

Never kick it from a timer ISR; that can hide a wedged main loop. At boot, read
the reset-cause register and log it before clearing it. `RCC_CSR` is an
example on STM32; use the exact register and bit definitions from the target
datasheet:

```c
uint32_t cause = RCC->CSR;
log_reset_cause(cause);
RCC->CSR |= RCC_CSR_RMVF;
```

## Clock bring-up

Follow the datasheet sequence and verify readiness at each gate:

1. Enable the HSE (or selected oscillator) and wait for its ready bit.
2. Configure and enable the PLL; wait for PLL lock.
3. Switch SYSCLK to the PLL and confirm the switch status.
4. Set bus prescalers and flash wait states.
5. Enable each peripheral clock.
6. Configure each peripheral.
7. Enable each peripheral and its interrupts/DMA.

Do not configure a peripheral before its clock is enabled. Record the final
clock tree in `lode/clock-tree.md`.
